      exakit source <action>

      A source record owns its local connection and virtual schema. It also tracks the shared artifacts it depends on.

      list reports saved state. issues filters recorded expiry and failures. check runs a fresh test. reauth accepts replacement credentials from the user; the kit does not issue or automatically renew them.

      disconnect deletes only the named CONNECTION object and marks the instance disconnected. remove also cleans up its owned setup and files that no other connection or runtime consumer needs.

      Source commands explained · disconnect versus remove

      sales identifies one saved connection instance. These are the module’s planned commands. --dry-run shows the plan without applying it. Applying disconnect or removal requires confirmation.

      CommandPurpose and example
      exakit source listList saved connections, connector types and last-observed states with check times. Listing does not run a fresh source test.
      exakit source issuesList recorded expiry and failed checks with evidence, time and the appropriate next action. Use --status expired for expiry only. Report unknown and skipped coverage separately. This command does not contact sources.
      exakit source show salesShow the endpoint, scope, object names, artifact pins and last result for sales. Hide passwords, tokens and key contents.
      exakit source check salesTest runtime network/TLS, authentication, metadata and a bounded source read as the intended reader. Record the result and time.
      exakit source check --allRun one bounded check for each configured connected source and update its saved result. Skip intentionally disconnected sources. Report every result, including unknown or incomplete checks. This is a one-shot operation, not background monitoring.
      exakit source reauth salesAccept replacement credentials obtained from the source owner or identity provider through protected input. Update the existing credential and verify a fresh read. For S3 temporary credentials, replace access key ID, secret access key and session token together. Reauth does not obtain credentials from AWS or change a source password. A disconnected instance first needs its CONNECTION recreated.
      exakit source refresh salesRefresh exposed table/column metadata after reviewing source changes. It does not renew credentials or copy all source rows.
      exakit source update sales --dry-runPreview approved adapter, driver or runtime changes, required restarts and affected shared consumers. It does not upgrade the external database server.
      exakit source disconnect salesDrop only the owned named Exasol CONNECTION, then record sales as disconnected. Keep its virtual schema, source definition and installed files. Add --dry-run to preview.
      exakit source remove salesAfter preview and confirmation, remove the owned virtual schema, CONNECTION if still present, source state and managed secret files. Unregister and delete setup artifacts only when owned by this module and unused elsewhere. Add --dry-run to preview.

      Disconnect is an object-only operation. It leaves the virtual schema configured but without its named credential object. It does not cancel in-flight sessions, revoke credentials at the source, erase retained key files or promise immediate access revocation. If ownership or shared usage is ambiguous, refuse the operation and explain the dependents. Do not silently delete the virtual schema to make disconnect succeed.

      Proposed: one JSON result with an actionable error and a runnable remedy when available. Preserve the kit’s existing exit-code meanings. Final source-specific error codes remain a design decision. An unattended run must supply all required input and explicitly consent to any restart.

      Connection count and installed file count are different

      Ten PostgreSQL instances with the same compatible pins share one adapter/driver file set in a deployment. Each keeps separate configuration, credentials and virtual schema objects. Different versions, architectures or runtime fingerprints require distinct payloads or an explicit compatibility refusal.

      Measured examples, 23 October 2026. These versions illustrate storage for the 11 Phase 1 connectors. They are not new approved support pins, and this size review does not clear the qualification gates on the GA slides. Native examples target Linux x86_64, including Windows Podman. macOS/ARM requires separately matching artifacts. 1 MiB = 1,048,576 bytes.

      Model: one retained file set per sampled connector version in one deployment. Runtime payload means deployed JAR/Lua/native files, not Java heap or query memory. SLCs are excluded unless checked. Their modeled deployment includes a runtime archive plus expanded files, as well as an optional host cache. No database is contacted by this calculator.

      Measurement method, package contents and storage exclusions

      Adapter/Lua sizes come from the public GitHub release asset metadata. Standalone JDBC sizes come from the vendor-published Maven artifacts’ Content-Length headers, using versions named by the sampled adapter POMs. Archive measurements use downloaded bytes and archive file listings, without installing or executing the contents. GitHub archive SHA-256 values matched the release metadata. The measured Simba ZIP digest appears below because a versioned URL alone is not a content pin.

      Most JDBC rows count a distribution JAR plus the standalone driver used by the documented import path. PostgreSQL and Snowflake distribution JARs already bundle driver code, but their guides still show a separate driver for registration. Document adapters bundle their SDK dependencies and need no vendor JDBC JAR. Databricks uses a Lua file plus its JDBC JAR. BigQuery uses an adapter plus all 75 JARs in the sampled Simba ZIP. The native rows count expanded archive files, not JARs.

      Not included: source-state JSON, generated SQL/scripts not already in an archive, mappings, licenses/notices fetched separately, credentials, database catalog storage, logs, query spill, copied source data, base Exasol/Podman images, filesystem allocation, compression/deduplication by the VM, backups and extra staging/rollback copies. Peak installation/update space can exceed retained space. Keep old pins while needed for rollback or by another consumer.

      Deployment copies: the default counts one runtime copy of each listed artifact. Check the extra-driver option only when Java and ETL paths require separate physical copies. It adds the standalone drivers for PostgreSQL, MySQL, SQL Server, Oracle, Snowflake and Databricks; BigQuery’s selected Java-only path has no ETL copy. Actual BucketFS replication, extraction caches and additional deployments can increase the total. Confirm paths and reference counts from the runtime provider.

      Beta profiles: E uses Lua scripts rather than JDBC JARs; F can need Python dependencies and a Python SLC. Those connector-specific packages are outside this 11-item measurement and must not be treated as zero-cost. Redistribution rights and license notices remain separate from byte-size evidence.

      Implementation

      Lightweight shell and PowerShell entry points can call a shared Python coordinator using the kit-managed Python environment. Treat that environment as a prerequisite. This is a proposed way to avoid duplicating security and state logic, not an existing module.

      Keep discovery in the core CLI. Download only the selected, pinned adapter and driver after showing the plan. Install/upgrade requires checksums, license acceptance where needed and an explicit restart decision.

Update plans must preserve or restore grants and test every dependent source.

Document adapters use import UDFs, Rust connectors use native scan UDFs, and local Exasol Lua can return local SQL. A LIMIT in the final query does not guarantee minimal remote work or cost.

      What happens after the user presses Connect?
      1. Validate names and endpoint input. Resolve the selected deployment and inspect existing dependencies. Refuse collisions with objects the kit does not own.
      2. Preview downloads, shared-runtime impact and data access. If Java or driver registration requires a restart, ask first and combine changes into one restart.

      07 / Security and credential renewal

      Access boundaries and renewal are part of the connector

      A connection is ready only when the intended reader can query the allowed data and the failure path is understood.

      Least privilege at the source

      Use a dedicated read-only source identity. Limit its accessible tables, collections or buckets. Verify TLS certificates and hostnames.

      Controlled access in Exasol

      Restrict connection access to the required scripts/owner. Grant the intended reader access to the virtual schema. Test using that identity, not only admin.

      Explicit agent data exposure

      The kit’s current MCP user has broad read privileges. A new virtual schema can expose new data to AI clients. Preview that exposure before connecting.

      Secret-safe operations

      Use hidden input and in-memory SQL calls. Redact URLs, driver errors and JSON fields. Verify artifact checksums. Review upstream security limitations before enabling a connector.

      Credentials refusedA query or explicit check fails. Classify authentication separately from TLS and network failures.

      Expiry, Windows credential storage and known limits
      • Detection: record last success and known expiry time. The CLI cannot observe every query from arbitrary SQL clients. Monitoring requires an explicit scheduled check. A sleeping laptop cannot provide dependable background renewal.
      • Renewal: v1 can use manual replacement. Add automatic OAuth/SDK refresh only for a tested adapter/provider connector. Short-lived cloud credentials can contain multiple fields that must change together.
      • Host storage: default to no saved copy of external-source secrets. If a later “remember” option is needed, use the OS credential store, such as Windows Credential Manager or current-user DPAPI, with restrictive file ACLs. Never fall back silently to plaintext.
      • Windows boundary: a Linux adapter cannot consume a Windows DPAPI blob. The host must decrypt in the correct user context and securely update the runtime CONNECTION. Database access controls and backup protection still apply.
      • Current MCP boundary: CREATE SESSION, USE ANY SCHEMA and SELECT ANY TABLE make it broadly read-only. A default schema name does not narrow access. Narrower exposure needs a separately approved privilege model.
      • Release gates: Databricks documents TLS/token-handling limitations. Document-file adapters publish a query-crash warning. Qualify selected versions and failure cases before calling these kit-tested. MongoDB currently documents source distribution and a matching Rust build/runtime requirement.

      disconnect --dry-run previews deletion of only the owned CONNECTION object.       Windows implementation checklist and acceptance gate

      Platform implementation

      • Use Join-Path for host paths and test spaces/Unicode. Keep host paths separate from Linux paths.
      • Write settings.cfg in the driver’s required format. Validate encoding, line endings and the final blank line.
      • Verify the runtime sees staged files. Use the deployment mapping instead of copying into an ephemeral container layer.
      • Reuse dependencies where compatible. Combine required changes and ask before a database restart.
      • Protect host records with user ACLs. Inspect key-file handling from both Windows and Linux if a connector requires one.

      Qualification before release

      • Clean Windows install, existing rootless machine, corporate VPN/proxy and custom CA.
      • Remote source and host-local source, including IPv4/IPv6 and listener/firewall restrictions.
      • Bad password, expired token, denied tables, broken TLS, interrupted download and failed restart.
      • Credential renewal, schema refresh, update/restart persistence and two sources sharing one driver.
      • Query with the MCP reader. Confirm secret-free logs and safe removal of only owned resources.

      Do not switch rootful/rootless mode, alter firewall rules, reset a Podman machine or delete volumes as an automatic connector repair. Such changes can interrupt other workloads. Request separate consent for machine changes. A WSL-installed kit is a separate execution context from the native Windows PowerShell kit.

      Suggested first release gate: PostgreSQL end to end on macOS, Linux and Windows. Then qualify MySQL and SQL Server individually. Expand to mapping, API and native profiles after their own security and lifecycle tests. A second source type can require a new driver even when it shares a category.

      Evidence boundary: the file mapping and Podman model follow upstream documentation and the kit’s current guide. This architecture page does not claim a Windows deployment or integration test was run.

      Credential flow, Windows Podman and implementation sequence
        
      Secrets: protected prompt/input → coordinator memory → secure Exasol session → named CONNECTION for most sources. BigQuery is a file-backed exception: protected transfer → isolated Linux key file; CONNECTION stores only its path and non-secret JDBC settings. Block activation until isolation is proven. Source identities are not automatically the querying user’s identity. Never put secrets in argv, logs, URLs, saved SQL or source-state JSON.
      
        
      Windows: exakit.ps1 calls the same coordinator through managed Python. The runtime provider resolves the persistent Personal deployment and maps Windows host paths to Linux BucketFS/JDBC paths. Stage Linux-compatible files, write driver settings with LF, and prove DNS/TLS/read access from the Exasol runtime. Windows sign-in, a host AWS login and localhost addresses are not automatically usable inside Podman.
